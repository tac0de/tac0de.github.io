GET STARTED

One walkthrough.
The complete local loop.

Install Node.js 24+ and Chrome/Chromium, then get the source. The runner needs no package installation.

git clone https://github.com/tac0de/tac0de.github.io.git css-agent-learning
cd css-agent-learning
node scripts/agent-css/main.mjs demo /tmp/css-learning-demo

Use a new destination directory. Open /tmp/css-learning-demo/report/index.html when the command finishes. Set AGENT_CSS_CHROME if your browser is in a different location.

The demo uses prescribed CSS, not an AI. Both target conditions receive the same correct solution. It proves the workflow runs, not that agents learn.

What runs where?

Does the website run or train my agent?

No. Your existing coding agent runs locally or in its own authorized environment. This site provides static materials. Reports are generated locally; the platform does not update model weights.

How do I compare with and without experience?

Use pair to prepare baseline and recall. Run each in a fresh agent session with the same model and limits, then use compare. Only recall receives prior experience. Any protocol and usage data are declared, not attested.

Which CSS is supported?

The first track checks checkbox logic and visibility at 800×600. CSS escapes, remote resources, motion declarations and focus/hover/active/target/link/user-validity selectors are excluded. Fixed HTML keeps native keyboard focus styles. This is not a full CSS, design or accessibility benchmark.

What if a check is interrupted?

Inspect the retained lock and confirm the recorded process ended. Never delete records or a lock just to bypass an error. Use a fresh workspace if recovery is unclear. Local records are editable and are not signed evidence.
