# AI 에이전트용 CSS 학습 플랫폼 — 제품 정의와 요구사항

상태: 2026-09-10 검토한 플랫폼 요구사항. 첫 로컬 평가기 구현을 추가했다.
전체 플랫폼 구현 완료나 학습 효과 검증을 뜻하지 않는다.

현재 구현 범위: 정적 안내·카탈로그, AND/XOR 연습과 별도 전이 과제, 로컬 평가,
실패 경험 기록, baseline/recall 작업 분리, 선택적 비용 기록과 HTML/JSON 비교 보고서다.
실제 사용 안내와 정해진 CSS로 실행한 예제 보고서를 기존 Pages에 배포한다.
자동 커리큘럼과 실제 모델 학습 효과 실험은 포함하지 않는다.
상세 구현 계약은 `agent-learning-loop.md`, 사용법은 `../public/learn/agent-guide.md`를 따른다.

## 확정한 목적

사용자는 인간 대상 해설 사이트가 아니라 AI 에이전트가 CSS 과제를 풀고,
피드백으로 수정한 뒤 새로운 CSS 문제에 적용하는 학습 플랫폼을 원한다.
최종 목표는 플랫폼이며 백엔드는 없다. 첫 과제는 전체 목표를 대체하지 않는다.
기존 브라우저 출력은 HTML/CSS 전용이며 런타임 JavaScript와 canvas를 사용하지 않는다.

플랫폼은 과제 발견 → 작업 준비 → CSS 작성 → 검증 → 피드백 → 수정 →
경험 기록 → 새로운 과제의 공통 흐름을 제공한다. 에이전트 모델의 가중치를
훈련하거나 플랫폼이 모델을 직접 호출하는 것은 이 범위에 포함하지 않는다.
사람은 과제를 제작하고 실행 결과를 점검할 수 있지만 주 학습 대상은 에이전트다.

## 현재 근거와 한계

- 기존 Lumen/Glyph/Relay 9개 퍼즐은 과제 소재와 시각적 예제가 된다.
- 현재 `scripts/verify.mjs`가 236개 상태와 137개 광선 구간 및 production
  no-JS 검사를 통과했다. 이 결과는 기존 게임의 정확성에 대한 근거다.
- `scripts/check-puzzles.mjs`는 제한된 선택자/선언을 직접 해석한다.
  임의의 CSS 제출물에 대한 브라우저 평가기 또는 학습 효과의 근거가 아니다.
- 실제 에이전트의 연습 전후 능력 향상, 새 문제 전이, 비용 절감은 미검증이다.
- 기존 게임 소스에는 정답이 있다. 기존 게임을 그대로 낸 결과는 처음 보는
  문제 성능으로 보고하지 않는다.

## 선택지와 제안

| 방향 | 유지보수·확장성 | 완성 속도·에이전트 경험 |
|---|---|---|
| 보수적: 게임과 과제 설명 파일만 배포 | 유지보수는 작지만 검증·기록이 제각각 | 빠르지만 사용 에이전트마다 실행 방법을 만들어야 함 |
| 제안: 정적 과제 카탈로그 + 공통 로컬 실행 도구 | 버전 있는 과제/결과 계약으로 확장, 로컬 브라우저 관리 필요 | 처음 설정한 절차를 다음 과제에서도 재사용 |
| 적극적: 다중 브라우저·다중 CSS 영역·자동 커리큘럼 | 호환성·평가 범위와 유지 비용이 크게 증가 | 넓은 플랫폼이지만 첫 완결 흐름이 늦어짐 |

공통 로컬 실행 도구를 중심으로 먼저 한 트랙을 완성하는 안을 제안한다.
학습 기록은 에이전트가 읽을 수 있는 파일로 제공한다. 에이전트가 그 기록을
실제로 읽고 활용했는지는 실행 기록에 구분하며 자동 학습을 보장하지 않는다.

## 첫 플랫폼 범위 제안

1. 정적 시작 안내와 기계가 읽는 버전 있는 과제 카탈로그.
2. 고정 HTML, 과제 설명, 수정할 CSS 파일, 검증 계약을 포함하는 과제 묶음.
3. 로컬 도구의 과제 목록·준비·검증·기록·결과 요약 기능.
4. Relay 기반 입력 상태 트랙: AND/OR/NOT/XOR 연습과 조건 조합 과제.
   기존 게임의 선택자와 정답을 복사하는 과제만으로 구성하지 않는다.
5. HTML 구조와 조건을 바꾼 별도의 전이 평가 과제. 첫 제출과 수정 후 결과를 분리.
6. 같은 과제 형식으로 새 과제를 추가할 수 있는 제작 안내와 계약 검사.

제출물은 CSS다. 퍼즐을 조작해서 승리 상태를 찾는 것은 과제 목표가 아니다.
초기 트랙은 입력과 출력의 상태 동작을 평가한다. CSS 전반, 시각 디자인,
반응형 레이아웃, 접근성 역량 전체를 측정한다고 주장하지 않는다.
Glyph/Lumen은 후속 과제 후보이며 첫 구현의 필수 범위가 아니다.

## 사용자 흐름과 인수 조건 제안

| ID | 관찰 가능한 조건 |
|---|---|
| A1 | 에이전트가 카탈로그에서 요구 환경·목표·과제 버전을 읽고 작업을 준비한다. |
| A2 | 고정 HTML과 평가 파일은 그대로 두고 CSS 제출물만 변경한다. 변경 위반은 명시적으로 거부한다. |
| A3 | 입력 조합 전체에 대해 실제 브라우저에서 출력 표시, 조작 가능성, reset을 검사한다. |
| A4 | 실패 결과는 과제/제출물 버전, 실패 상태, 기대/관측 결과, 검사 오류를 기계 판독 형태로 제공한다. |
| A5 | 에이전트가 실패를 수정하면 새 제출물의 검사 결과가 별도 기록되고 이전 기록이 보존된다. |
| A6 | 평가 실행은 상세 피드백 이전의 첫 제출을 표시한다. 수정 후 성공을 첫 제출 성공으로 집계하지 않는다. |
| A7 | 새 과제를 같은 계약으로 추가하면 공통 도구를 수정하지 않고 목록·준비·검증할 수 있다. |
| A8 | 서버 API·DB·계정·서버 모델 호출 없이 수행하며, 웹 산출물에는 런타임 JS/WASM이 없다. |
| A9 | 기존 게임 9개와 필수 검증이 유지되고 기존 게임 상태 파일은 교체하지 않는다. |
| A10 | 브라우저 부재·잘못된 제출물·실행 시간 초과는 CSS 오답과 구분되고 점수로 위장되지 않는다. |

인수 조건은 플랫폼 동작의 기준이다. 학습 효과 실험에는 모델/버전, 지침,
도구, 토큰·시간·시도 한도, 문제 난이도와 정답 노출 여부를 맞춘 비교가 필요하다.
연습 전후에는 서로 다른 대응 문제 묶음을 사용하고 가능하면 순서를 교차한다.
표본 수와 효과 기준은 실제 실험을 설계할 때 정한다. 현재 수치 효과는 약속하지 않는다.

## 의도적으로 제외하는 것

계정, 서버 저장, 순위표, 원격 채점 API, 자동 모델 호출, 모델 가중치 훈련,
샌드박스 보안 인증, 공정 경쟁 인증, 새 배포 구성, 새 의존성 추가. 기존 Pages 배포는 사용자가 승인했다.
로컬 기록은 편집될 수 있고 공개 과제·검사 코드는 읽을 수 있다.
독립된 검사 코드는 우발적인 변경을 막는 구조이며 비밀 시험이나 부정행위 방지 장치가 아니다.

## 구현 전 확인할 기술 조건

설계는 Node와 별도 로컬 Chromium을 사용하는 안이다. 현재 개발 환경에는
Node 24.2와 Chrome 152가 있고 임시 프로필의 inspector pipe 제어를 실제 확인했다.
임시 프로필·로컬 파일·브라우저 제어 경로가 프로젝트 규칙과 환경에서 동작하는지
작은 검증기로 확인한 후 지원 환경을 명시한다. 실패하면 환경 오류로 보고하며
제한된 선택자 해석기로 조용히 대체하지 않는다.
